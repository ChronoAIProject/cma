## Activation and rollback qualification

| Process switch | Durable writer gate | Result |
| --- | --- | --- |
| Absent / false | Absent, closed, or enabled | No adoption preflight or gate query; ordinary v1 publication follows the original operation sequence. Existing v2 publication remains available. |
| True | Absent / closed / unselected | Discovery still occurs; no new adoption is authorized. Exact already-admitted work can continue according to the original protocol. This is not a zero-overhead rollback. |
| True | Enabled and Agent selected | Natural append can adopt through the reviewed durable protocol. |

The zero-overhead claim is specifically for the process switch off/absent. Closing only the durable cohort gate while leaving process dispatch on does not restore the original command counts. The PR body and operations document state this explicitly.

The earlier gate-only writer packet must be updated and re-sealed before activation: enable process dispatch as well as the durable cohort gate. Rollback first closes durable admission, resolves/drains exact admitted uncertainty while dispatch stays enabled, then rolls process dispatch off. Retain v2-compatible readers. This is an activation-packet prerequisite, not a merge blocker for the default-off fix.

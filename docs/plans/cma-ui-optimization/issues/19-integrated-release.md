# 19：验收整套任务体验并准备分批发布

**What to build:** 用户从首页开始、观察运行、获取成果、评价和继续任务的完整体验经过组合验证，新旧客户端与未完成任务可以安全共存。

**Blocked by:** 01、02、04、05、06、08、10、12、13、16、17、18（各功能分支的直接叶子，其余票由这些依赖传递覆盖）。

**Status:** in-progress — 技术实现与有界组合验收完成；13 literal human 质量、parent 最终历史/Standards/Spec gate 仍待完成。

**优先级:** 全套交付门槛；已验收单票可先灰度

## Acceptance criteria

- [ ] 每个前置票都有自身验收证据；本票不代替其 red → green 测试，不用一条 happy path 证明全部错误恢复与运行时能力。
- [x] 主路径覆盖：首页任务→准备/首任务→任务名/状态→计划/活动→文件卡片/预览/下载→评价/原因→建议直接发送/编辑→第二轮正常工作。
- [x] 环境路径覆盖可选仓库与桌面同时选择、真实浏览器、接管/归还、操作回放/返回实时；过程摘要和回放入口指向同一 turn。
- [x] 支持能力缺失的环境也有完整可用的手动对话流程；没有 Live 的环境不伪造 Live、没有计划不伪造百分比；浏览器/接管票仍需真实能力证据才能算完成。
- [x] 桌面与移动端验证布局、44px 热区、长文本、键盘、读屏与 reduced motion；预览/原因/建议展开不遮挡 composer，不丢草稿、附件、滚动位置。
- [x] 组合故障覆盖丢响应后刷新、跨 Agent 快速切换、换号、权限撤销、新旧客户端混用、跨标签新任务导致旧建议失效、任务运行中重连；未完成工作与原请求身份保持。
- [x] 原有文件编辑/下载、回答复制/反馈、审批、共享读取、排队/打断/停止继续工作，旧 transport 选择不被新开关强制迁移。
- [x] 分项记录首任务成功准入、确认延迟、重复投递、文件失败、反馈失败、建议生成延迟/费用和浏览器资源数据；分母、去重和业务终态明确，不只报告点击率。
- [x] 发布按能力/账号渐进开关，规定回退条件与观察窗口；关闭新 UI 不删除 durable 请求/成果/评价，不打断运行中 Sandbox，不回退到无法读取新记录的旧 schema。
- [ ] 汇总相关类型、构建、测试、契约、样式与真实浏览器验证结果；较大改动审查实际行为和规范，未通过项明确保持未完成。
- [x] 发布材料包含分票 PR 建议、前后截图、固定 runtime 证据与兼容/回滚说明。合并或部署需另行执行，不把“已准备发布”写成“已上线”。

## Testing boundaries（2026-11-03 已确认）

- **U + A + R：** 用隔离账号/Agent 完整跑跨功能路径，保留截图、公开返回和真实 runtime 观测；不操作用户生产任务。
- **遗漏说明：** 有限验收不证明无限规模性能或所有未来 runtime 版本；报告实测规模、版本、设备尺寸和不支持能力。
- **首个 red → green：** 一次任务实际完成并交付文件，用户下载、给负评原因后编辑建议启动第二轮，原文件与评价刷新后仍存在，全部操作归属正确。

## 范围与依赖说明

仅检查组合行为与发布条件，不建立新的分析平台或重做所有单票测试。整套验收发现问题回到负责票修复，再重复受影响场景；没有证据的运行时能力不能以关闭开关替代交付。

# 11：从最新回答的场景建议直接继续对话

**What to build:** 用户在明确适用的场景看到最多三条后续提问，点击后可靠发送显示的原文；失败和切换不造成重复消息。

**Blocked by:** None（复用当前 Agent 的正常发送与恢复入口）。

**Status:** draft-review

**优先级:** P1

## Acceptance criteria

- [ ] 首版至少覆盖一个可证实的场景，例如明确的比较任务完成后提供“补充比较标准”；场景匹配规则可审查，不适用就不展示，不把固定模板宣传成动态智能生成。
- [ ] 建议集绑定 viewer/Agent/turn/最终回答身份、稳定建议 ID、可见文本和排序；候选 0—3 条，位于最新已完成回答的正文和成果后，只有一个“下一步可以问”区域。
- [ ] 用户消息、中间回复、生成中、无有效最终回答和已进入新一轮的旧回答均不显示可发送建议；只读/分享不显示发送入口。
- [ ] 点击发送的内容与完整可见文案逐字一致，立即显示发送状态；走当前会话已选择的正常 transport、审批、连接门禁和原请求去重机制，不新造发送端点。
- [ ] 保存当前手动输入草稿，建议直接发送不清空它；发送期间禁用该组重复发送，成功受理后才收起该组。点击反馈只保存评价，不能触发建议发送。
- [ ] 明确拒绝可重试同一文本；不确定接收保留原内容与请求身份，先核实原请求结果。重复点击/超时恢复只形成一条用户消息和一次合法任务准入。
- [ ] 切 Agent、换号、回答被替代或收到另一用户消息时取消/忽略旧请求；发送时再次校验当前回答及权限，含另一标签页先发送导致的失效。必要的条件准入与公开契约同票补齐。
- [ ] 模板结果按回答身份和模板版本稳定重建；刷新不能给新回答套旧建议。无建议/加载失败不影响正文和手动输入，发送失败保留明确恢复入口。
- [ ] 无建议、1—3 条、发送中、失败、权限失效与快速切换在键盘/触屏均可操作，文本不被截断到改变发送含义。

## Testing boundaries（待确认）

- **U：** 完整会话中的建议→消息流/草稿/下一轮；捕获组禁用、视觉区分和失效请求。不能以 mock 调用一次证明服务端不重复。
- **A：** 正常发送准入和公开历史回读，丢响应/恢复/双标签过期场景下验证一条正确归属的消息；不以文字相同合并不同用户意图。
- **首个 red → green：** 输入框已有草稿时双击一条建议并丢失首个回执，恢复后历史恰有一条建议原文，原草稿仍可编辑。

## 范围与依赖说明

有无成果都可以继续对话，因此不依赖 07。12 增加编辑入口，13 替换/扩展建议来源为上下文生成，整项功能不能以模板版本宣布完成。

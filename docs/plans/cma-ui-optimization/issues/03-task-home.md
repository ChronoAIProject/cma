# 03：在首页直接提交并可靠启动一项任务

**What to build:** 用户在首页输入一句任务就能进入自己的 Agent；创建、首条任务、刷新及响应丢失属于同一条可恢复链路。

**Blocked by:** None（评审确认后可独立开始）。

**Status:** ready-for-agent

**优先级:** P0

## Acceptance criteria

- [ ] 登录后的首页呈现主输入框和调研/表格/文档/网页/代码等模板；模板只填入可编辑草稿，不创建 Agent、不自动发送。未登录仍走已有登录入口。
- [ ] 首页、侧栏 New agent 和正常快捷入口进入任务输入，不再先弹配置表单；在已有 Workspace/Sandbox 中创建时保留明确上下文及原授权检查。
- [ ] 发送冻结任务原文和创建上下文；服务端持久记录后给出 operation receipt，区分 operation ID 与 Agent ID，接受不等于执行完成。
- [ ] 将首条任务纳入生命周期原请求与幂等比较；同 owner、同 key、同内容恢复同一结果，改内容复用 key 得到明确拒绝。连续点击、丢响应和 worker 重启不产生第二个 Agent 或第二条任务。
- [ ] 自动 setup 与真实 task 的目的、时序和状态清楚；准备完成不能冒充用户任务完成。无 initial task 的旧客户端保持原有 setup 行为。
- [ ] 一旦确切 Agent 身份可读即可进入准备中的会话并看见任务状态，无需等最终执行成功才导航；启动、连接授权、任务拒绝各有独立可恢复状态。
- [ ] 绑定 viewer/origin/创建上下文的首页草稿在同一标签页刷新后恢复；已发送请求保留冻结原文/key/receipt，已受理操作以服务端记录为准。退出或换号清理，重新鉴权后才能恢复；不承诺跨设备草稿同步。
- [ ] 未确认请求不可自动换 key 重建；网络拒绝保留原任务和后续新草稿，恢复旧请求的回调不会覆盖新输入。存储不可用时在发请求前提示并保留可复制文本。
- [ ] 空白、超出约定字节上限、缺少创建权限均有可见错误；浏览器前进/返回、刷新和权限失效不自动重新提交。
- [ ] 公开契约、持久记录兼容及运行时首任务行为随页面一起交付；服务端不支持本能力时显示可理解的不可用状态。

## Testing boundaries（2026-11-03 已确认）

- **U：** 首页输入→提交→准备中的 Agent→失败/恢复；覆盖同标签刷新、账号变化和晚到回调。不能单独证明服务重启后的投递。
- **A：** 公开创建/操作查询/Agent 历史，注入丢响应和服务重启后读取同一操作与唯一用户任务；不以私有存储断言替代历史。不能证明 provider 真正收到文本。
- **R：** 固定 runtime 的隔离 Agent 收到确切任务并返回结果，覆盖一次不确定发送恢复。不能穷举所有停机点，持久性故障矩阵仍由 A 覆盖。
- **首个 red → green：** 首页发送“比较三个工具”，创建被受理后刷新，通过同一操作进入唯一 Agent，历史只出现一次该任务。

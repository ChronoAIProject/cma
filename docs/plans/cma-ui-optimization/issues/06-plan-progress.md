# 06：展示真实计划进度与当前活动

**What to build:** 用户能看到 Agent 已完成哪些步骤、当前在做什么，并按需展开原始操作；完成后过程可收起。

**Blocked by:** None（复用已有 PlanSet 和工具事件）。

**Status:** draft-review

**优先级:** P1

## Acceptance criteria

- [ ] 固定 runtime 的真实计划事件能够经公开流和历史重放呈现；检查已有 ACP/PlanSet 投影并只补缺失环节，不为显示卡片创建第二种计划源。
- [ ] 已完成/当前/未开始各有明确文本与图标；已知计划为完成、执行中、待开始三步时显示“已完成 1/3、当前第 2 步”，进度条可被读屏理解。
- [ ] 同一 turn 新计划替换旧计划，去重重连事件；重排、清空、未知状态和多个 in_progress 不虚构稳定步骤 ID 或完成比例。按设计取第一个当前步骤并允许展开全部。
- [ ] 无计划显示真实当前活动/Thinking，不能从工具次数猜总步数；当前活动用已报告的安全描述，无明确关联时不称其属于某一步。
- [ ] 工具调用默认折叠并显示操作数量，失败和需用户处理事项始终可发现；审批不藏在折叠组里。
- [ ] 成功且计划全部完成时可显示“已完成全部 N 步”；成功但计划未全部报告完成、失败、取消各有准确摘要，不补写 completed。
- [ ] 无可靠估计来源时隐藏预计剩余时间；已报告估计带来源/更新时间，过期即撤下，不把进度比当耗时预测。
- [ ] 活跃计划、历史计划、顶栏摘要与完成折叠保持同一 turn scope；新轮不继承旧计划，用户阅读历史时更新不强行滚到底。

## Testing boundaries（待确认）

- **U/A：** 公开事件/重放→会话页面的计划和状态，固定三步例子、重连、清空及失败；验证可见行为而非私有 presentPlan 函数。不能证明 provider 在所有任务都产出计划。
- **R：** 在固定版本获得至少一份实际计划与一次变更，并验证重连；provider 未发计划时验证降级，不把缺失事件伪装为支持证明。
- **首个 red → green：** 已完成一步、正在执行第二步的三步计划，断线重放后仍只有一张当前卡片，显示 1/3 和第 2 步。

## 范围与依赖说明

使用现有工具摘要，不等待浏览器或操作回放。18 交付后才增加真实回放链接，未接入前保留“查看计划和操作”，不放空入口。

# 02：简化输入设置并显示真实完成耗时

**What to build:** 用户用一行摘要了解模型和权限，必要时展开设置，同时看懂补充消息何时处理和当前任务耗时。

**Blocked by:** None（评审确认后可独立开始）。

**Status:** in-progress

**优先级:** P0

## Acceptance criteria

- [ ] 模型、推理与权限收进紧凑摘要及设置入口；修改仍走原有能力检查、空闲约束、显式应用和不确定请求恢复。
- [ ] 排队与打断的用户文案反映实际 transport 能力；排队表示当前轮结束后处理，不承诺未实现的“下一步之前一定读到”。
- [ ] Send、排队、打断、Stop、审批和 pending recovery 均可操作；本票不改变已有协议值和权限级别。
- [ ] 在顶栏显示最后一轮的确认完成耗时；例如记录开始 10:00、成功结束 10:04 时显示“4 分钟完成”。失败/停止不显示成功完成。
- [ ] 历史缺少开始或结束时间时省略耗时；不足一秒使用“小于 1 秒”，不把缺失值显示为 0 seconds；新轮开始不沿用上一轮耗时。
- [ ] 设置开关、顶栏更新和长文本不清空草稿/附件、不重挂载 composer；移动端触控、键盘与读屏状态正常。

## Testing boundaries（2026-11-03 已确认）

- **U：** 已有会话页面的输入、设置、发送、停止及顶栏；用固定事件时间验证用户可见结果。不能凭 fixture 证明实际队列时序。
- **A/R：** 对当前支持的 AG-UI/Responses 路径各验证适用的发送/控制行为，已有 transport 选择不因设置更新改变。不能替代布局验证。
- **首个 red → green：** 用户有草稿时展开并关闭设置，正文与附件原样保留，发送仍提交同一内容。

## 范围与依赖说明

不依赖计划步骤或自动命名；运行耗时来自现有事件时间。02 与 06 共享顶栏，合并时协调插槽，避免重复状态摘要。

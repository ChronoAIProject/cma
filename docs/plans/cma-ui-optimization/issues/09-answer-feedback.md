# 09：评价一条已完成的最终回答

**What to build:** 用户在最终回答底部一键表达有帮助/需改进，刷新后恢复评价，操作不会启动新一轮任务。

**Blocked by:** None（已有消息级 vote 契约可复用）。

**Status:** draft-review

**优先级:** P0

## Acceptance criteria

- [ ] 仅已记录、所属 turn 已结束且被确认为最终回答的 Assistant 消息提供评价；用户消息、思考、工具日志、流式片段和只有失败提示的消息不提供入口。
- [ ] “最终回答”的身份由会话的稳定消息/turn 语义确定；重新生成的不同回答各自保留记录，不依赖数组位置或内容相同判断。
- [ ] 点击有帮助/需改进保存 up/down；再次点击撤销，点另一项切换；成功后才显示已记录，同一回答保存期间避免重复提交。
- [ ] 保存失败保持最后确认的选择及可见重试；接收结果不明先核实/精确重试原动作，不直接允许相反写入掩盖未知结果。
- [ ] 重开与刷新恢复本人评价，换号/换 Agent 立即隔离旧请求与状态；分享或只读视图保留复制但不提供可保存评价。
- [ ] 评价不新增消息、不改变 Agent turn、不自动重新生成；服务端同样验证评价对象和身份，不能只在按钮处限制。
- [ ] 桌面 hover/focus 可访问，选中及反馈状态始终可见；移动端入口常显且热区至少 44px，成功/失败可被读屏播报。
- [ ] 兼容历史 up/down/null 客户端和既有已存评价，不能因收紧前端入口而删除历史记录。

## Testing boundaries（待确认）

- **U/A：** 最终回答→评价→公开读取恢复，核对原会话未新增 turn；验证 streaming、中间消息、只读及换号。不能判断回答本身正确性。
- **真实浏览器：** 选中状态、触控热区、键盘焦点和状态播报；不会把点击次数作为持久化成功断言。
- **首个 red → green：** 同一轮含一条中间消息和一条已提交最终回答，仅后者能评价，刷新后恢复其 vote 且会话轮数不变。

## 范围与依赖说明

复用现有 vote 服务与失败恢复；原因面板属于 10，基础版本不展示无法保存的表单。

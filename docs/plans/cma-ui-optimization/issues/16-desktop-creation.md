# 16：在首页选择共享桌面并启动可观察任务

**What to build:** 用户在任务输入框下选择是否启用桌面，提交后能在同一 Agent 的浏览器面板看到真实工作过程。

**Blocked by:** 03（可恢复的首页创建）；15（已证实的浏览器观察能力）。

**Status:** done

**优先级:** P3

## Acceptance criteria

- [x] 首页上下文提供可理解的可选桌面开关，默认关闭以保留当前成本；说明是否需要额外准备，能力不支持时给出原因而非假开关。
- [x] 桌面选择与任务原文绑定同一原始请求/key/operation，进入公开创建契约及持久恢复；省略字段的旧客户端维持原行为。
- [x] 明确支持的镜像/运行时版本和资源条件，真正不支持在资源创建前拒绝；暂时准备失败是可恢复故障，不能静默创建另一环境。
- [x] 创建中的“正在准备桌面”与任务处理状态分开；用户可先进入会话，首次真实画面到达后才显示 Live，不因连接画面而重复首任务。
- [x] 已存在 Workspace/Sandbox 的请求按真实能力处理：可支持则绑定原环境，需中断或重新创建才能支持时明确拒绝/说明，不自动重启在用 Sandbox。
- [x] 取消、失败、刷新和恢复保持原桌面选择与首任务；改选项必须明确作为新意图，不能修改已受理请求的语义。
- [x] 新 Sandbox 只在用户明确提交时准备，查看首页/选开关/OAuth 回跳不自行创建；浏览器权限仍与 Agent 身份绑定。

## Testing boundaries（2026-11-03 已确认）

- **U/A：** 首页选择→创建→进度→同一 Agent，检查请求恢复/能力拒绝及旧客户端兼容；不能只证明字段存在。
- **R：** 通过正式创建入口启用桌面的隔离 Agent，实际执行浏览器任务并在面板观察；记录该路径的准备时间与资源测量。
- **首个 red → green：** 选择桌面提交后丢失创建回执，刷新恢复得到同一 Agent、同一首任务和真实可观察浏览器。

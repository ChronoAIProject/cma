# 10：独立提交并修改负向评价原因

**What to build:** 用户点需改进后可补充原因，关闭或提交失败都保留已保存评价；撤销/切赞不会残留旧原因。

**Blocked by:** 09（最终回答归属与基础 vote 保存）。

**Status:** done

实施基线：`7739c431f`，独立 worktree `ticket-10` / `codex/cma-ui-10`。沿用已批准 U/A/R 边界；首条 A 边界测试为延迟原因请求在 up 后拒绝并公开回读无原因。存储修改另以隔离数据库验证真实 Mongo 并发。

**优先级:** P2

## Acceptance criteria

- [x] 点击需改进立即发起 vote 保存并展开非阻塞面板；不以填写原因为保存前提，提交原因需绑定已确认的负向评价。
- [x] 原因支持多选：内容不准确、没回答问题、步骤不可用、不够完整、表达不清楚、其他。说明选填，前后端统一按 Unicode 码点计数，最多 500 字，超限明确拒绝。
- [x] 提交原因独立于 vote mutation，返回本人/Agent/回答、已保存原因和更新时间；公开回读可以恢复，允许再次打开修改。
- [x] 关闭面板仅收起，本页按 viewer/Agent/回答保留未提交草稿；只有提交确认才覆盖已存原因，失败仅重试原因并保留原 vote 与草稿。
- [x] 撤销或从 down 切换 up 原子清除原因与说明；原因写入携带评价版本/条件，晚到的旧原因提交被拒绝，不能重新建立已撤销负评。
- [x] 切回 down 默认空原因；同一请求不确定重试不重复生成记录；换号/权限丢失清除旧用户原因草稿，不能继续提交。
- [x] 历史只有 vote 的记录按空原因读取；旧客户端 up/null 同样清除原因；迁移和公开契约兼容随本票交付。
- [x] 默认、已赞、负评展开、保存中、成功、失败和已撤销在桌面/手机可读，面板不遮挡答案和输入区。

## Testing boundaries（2026-11-03 已确认）

- **U/A：** 保存 vote→编辑原因→提交/关闭→刷新回读；控制响应顺序验证并发清理，公开接口验证 500/501 字、枚举和非 owner 拒绝。不能证明原因描述的事实正确性。

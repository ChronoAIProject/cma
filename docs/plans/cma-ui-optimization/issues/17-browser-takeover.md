# 17：安全接管并归还 Agent 浏览器控制权

**What to build:** 有操作权限的用户能显式接管正在观察的浏览器进行输入，再把同一浏览器交还给 Agent。

**Blocked by:** 15（真实浏览器身份、画面与能力已验证）。

**Status:** ready-for-agent

**优先级:** P3

## Acceptance criteria

- [ ] 只有运行时明确支持且用户有操作权限时显示接管；分享/只读、暂停或能力未知时不能发送浏览器输入。
- [ ] 控制权有明确的 agent/user/转移中/状态未知状态和持久或可核实的控制身份；接管回执前不宣称“你正在控制”。
- [ ] 接管成功后，同一浏览器中 Agent 自动输入被互斥阻止，用户实际点击/键入可观察；其他标签页或旧控制 token 不可并发写入。
- [ ] 归还控制权后用户输入立即失效，Agent 在原浏览器上下文继续；不重建会话、不丢页面状态，也不把归还按钮当用户新任务消息。
- [ ] 接管/归还回执丢失时查询原操作或精确重试；状态未知禁止双边输入，不根据超时直接宣称接管或释放成功。
- [ ] 控制租约过期、用户离线、账号/权限撤销及 runtime incarnation 改变采用明确的失效与安全归还策略；旧输入不能在新环境执行。
- [ ] 接管是浏览器操作权限，不是扩大 Agent 的服务授权，不绕过审批/外部操作规则；控制日志足以通过公开授权读取核实交接。
- [ ] 用真实键鼠输入、第二个竞争客户端和断线恢复证明互斥；只实现 disabled 按钮不能通过验收。

## Testing boundaries（2026-11-03 已确认）

- **A/U：** 授权控制请求、状态查询、状态显示与失效，验证并发主体及不确定请求。不能靠前端锁证明 runtime 互斥。
- **R：** 固定版本真实浏览器里用户输入实际生效、Agent 输入受阻、归还后恢复；租约失效和旧身份输入有可观察拒绝。
- **首个 red → green：** 用户接管后在测试表单输入已知文字，Agent 同时尝试输入被拒绝；归还后 Agent 能在同一页面继续。

## 范围与依赖说明

不依赖 16，因为明确启用的现有 Agent 已可接管。只接管浏览器，不增开 PTY 或全 Sandbox 任意桌面控制；若目标 runtime 无法做到互斥，本票继续保留为未完成能力。

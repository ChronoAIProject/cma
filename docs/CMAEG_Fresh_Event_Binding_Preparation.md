# Fresh-event binding preparation

This implementation is disabled by default for a separate replacement operation after a channel-owned Sandbox was explicitly retired and its home released. It does not enable automatic replacement in production. Ordinary binding PUT, conversation PUT and background recovery continue to preserve the original hierarchy. An entirely retired binding remains terminal.

## Retained authority and transaction

`BindingPreparationIntent` pins the durable event admission, target, request hash, owner, management principal, binding generation/revision and exact binding/Sandbox/Workspace digests. Its operation ID is a content hash of admission ID, target ID and binding ID. A new reservation requires a live admission whose timestamp is strictly later than the original Sandbox retirement. An event timestamp supplied by a producer is not an admission timestamp.

Only the dedicated `MongoBindingCredentials::prepare_retired` transaction can persist a generation change. It requires a Failed/Idle profile binding, no borrowed Agent or previous environment, a fully retired original Sandbox with released home, settled credentials and no active lifecycle, Workspace or child work. A retained Ready Workspace row does not establish that the released home still exists. The transaction validates indexed conversation records, requires all retained conversations to be terminal, refuses active child work and cleanup reservations, and writes exact parent fences.

The same transaction stores an immutable `provider_binding_preparations` receipt containing the complete original binding, a single reserved next generation and its new Sandbox/Workspace IDs. It admits the existing supplied key to encrypted custody for the new Sandbox and leaves durable `ProvisionSandbox` work. Original Sandbox, Workspace, conversation and history aggregates are retained; no original PV is changed or recovered by this operation. The receipt collection has no TTL and one unique `(binding_id, generation)` index, in addition to the operation ID. It belongs only to Agent Manager's existing exact-schema role and initialization mechanism.

Replays require exact intent equality and the same credential hash. Unknown commits may read back only the exact immutable operation receipt. They must never refresh expectations, generate a new operation key or infer a failed reservation from a transport error. A different event racing the same original generation cannot create a second hierarchy. Replaying a committed receipt after later lifecycle changes returns that receipt without allocating again.

## Generation readers

The optional `ProviderBinding.generation_guard` is omitted on existing records. Once present, a binding requires a matching positive `binding_generation` in Responses v2 submissions. Generation is checked before source-user routing, transport alias resolution and command admission. Conversation creation also has a generation-pinned core entry point; the original unpinned entry point refuses guarded bindings. Existing binding admission fences continue to protect the exact Agent and conversation at command admission.

The generic binding store still rejects every generation change, removal/change of the guard, and insertion of a fabricated guard. The dedicated atomic operation is the only writer. Old request bytes and unguarded bindings retain their current behavior.

Gateway readers understand an optional `binding_preparation_version` on new routed admissions, an optional binding preparation checkpoint on the execution journal and `binding_generation` on frozen turns. All fields are omitted on existing admissions and requests. The checkpoint records a pinned current generation, an inherited originating generation for native callbacks/message changes, the exact pending replacement intent, or the same intent with its immutable provider receipt. Only the ordinary Human Message admission shape can carry the explicit per-target replacement version. Journal CAS/readback confirms both intent and receipt writes after an acknowledgement loss; a different intent cannot overwrite the first. A frozen request must match the acknowledged checkpoint generation. Borrowed ExistingAgent targets keep their existing behavior even in a mixed-target admission.

The dispatcher handles preparation only in Pending phase. It rechecks current source/consumer/provider authority, renews its lease, writes the exact intent before the management POST, and writes the exact receipt before generation-pinned conversation creation. An ambiguous provider reply retries that same retained intent. Prepared, Starting, Unknown and accepted requests do not inspect or replace a hierarchy. Inspection and reservation use only the configured CMA management identity at the exact approved endpoints, never an agent-key fallback.

Fresh nonhuman events can pin the current generation but cannot authorize replacement. Native interactions and edits/deletes/reactions inherit the generation from their originating admitted target, using the authenticated native MessageRef or verified original event identity and the original sealed execution checkpoint. They never choose today's generation. A legacy origin has an explicit inherited `None` pin; CMA rejects it after migration instead of rerouting it. Missing/corrupt origin or an unresolved pending preparation fails closed. Historical leases are not acquired or changed.

## Authenticated management endpoints

`POST /api/v1/cmaeg/bindings/{binding_id}/preparation-inspections` is read-only. It authenticates the current management principal, both binding-management capabilities, the exact owner and the supplied binding key. A healthy/provisioning or recoverable original returns its current generation. Only an eligible fully retired hierarchy returns the exact digest-pinned replacement intent. Inspection never allocates IDs or mutates credentials, parents or binding state.

`POST /api/v1/cmaeg/bindings/{binding_id}/preparations` accepts that exact intent and the supplied key. It requires one `Idempotency-Key` equal to the derived operation ID. It reauthenticates the current manager/owner/key even for an immutable receipt replay and returns only the small receipt projection, never the archived profile or credential hash. Writes require `CHRONO_CMAEG_BINDING_PREPARATION_ENABLED=true`; this flag defaults to false and invalid values refuse startup. All endpoint responses are `Cache-Control: no-store`.

Conversation PUT accepts one positive canonical `x-cma-binding-generation` header. Both source-user fast acknowledgement and real Agent allocation enforce it. Responses v2 receives the corresponding `binding_generation` JSON field. Missing pins retain legacy behavior only for bindings without a generation guard.

## Compatibility and activation

All production writers remain disabled until explicitly configured. Ship the complete compatible reader set (including inherited generation and per-target replacement marker) in Agent Manager, Gateway and every rollback image before activating the writer. A rollback to an image that cannot read retained new fields is unsupported after the first migrated event.

1. Configure the CMA provider's optional `paths.preparation` with exact `inspection` path `/api/v1/cmaeg/bindings/{binding_id}/preparation-inspections` and `reservation` path `/api/v1/cmaeg/bindings/{binding_id}/preparations`. Current management authentication must be configured for the same exact origin and `cma_codex` provider. Other paths/origins cannot receive the management credential.
2. Enable `CMAEG_BINDING_PREPARATION_ENABLED=true` only after reader rollout and existing routed-recovery enablement. This begins generation-aware **new** admissions. Historical admitted plans retain their exact bytes and never acquire replacement authority on replay.
3. Set `CMAEG_BINDING_REPLACEMENT_BINDINGS` to an explicit comma-separated binding-ID allowlist (no wildcard). This captures replacement permission only on new ordinary Human Message targets for that binding. Empty/default selection authorizes no replacement. External/borrowed providers, interactions, callbacks, edits/deletes/reactions, generated events and legacy admissions never capture replacement permission.
4. Enable `CHRONO_CMAEG_BINDING_PREPARATION_ENABLED=true` on Agent Manager only after verifying exact-schema collection/index initialization and generation-reader compatibility. Inspection is read-only without this flag. Activate initially for an isolated test binding and verify one generation reservation, matching receipt, background Sandbox/Workspace provisioning, pinned conversation and response.
5. To stop **new** replacements, empty the Gateway replacement allowlist; keep generation preparation and compatible readers enabled so already migrated bindings continue receiving new ordinary events. Existing admitted Pending operations retain their immutable captured authority. Turning off Agent Manager's writer flag also pauses reservation/replay POSTs until restored; it does not discard their journal markers.

The three settings above default to disabled/empty, with strict parsing. This branch changes no production configuration.

These changes require no NyxID code, agent-sandbox controller or infrastructure development.

## Verification

Focused domain and routing tests cover unchanged old serialization, generation-change refusal, exact generation submission/replay and rejection before conversation allocation. Gateway journal tests exercise lost intent and receipt acknowledgements, expired lease takeover, immutable expectations and receipt-before-freeze ordering. Disposable-replica-set tests cover identical and distinct concurrent requests, full rollback after archive/custody writes, lost application acknowledgement with store reopen, preserved original aggregates/history, corrupt or foreign child records, cleanup reservation refusal and retirement races. Authenticated endpoint tests cover read-only inspection, current manager/owner/key checks, default-disabled writes, exact unique operation headers and generation enforcement for both conversation and source-user affinity. Gateway tests cover immutable retry intents, current-authority checks before mutation, receipt-before-conversation ordering, generation-only traffic with replacement disabled, and native origin inheritance. Both indexed and retained-record parent identity paths are indexed and checked, so a malformed lookup projection cannot hide a child. All Mongo fixtures use unique temporary databases and remove only those databases.

An authenticated Axum-to-Mongo integration test also exercises inspection, disabled and enabled reservation, replay, and credential rejection after a committed receipt. It checks the Gateway/core wire fingerprint, the single receipt and unchanged original Sandbox/Workspace aggregates. Separate real HTTP provider tests verify management authentication, exact operation headers and generation-pinned conversation creation. These checks do not establish production provisioning or platform delivery; activation still requires the isolated end-to-end check described above.

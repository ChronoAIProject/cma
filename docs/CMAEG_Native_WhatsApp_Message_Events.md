# Native WhatsApp incoming edits and revokes

Native WhatsApp sources can receive private incoming message edits and deletions for **WhatsApp Business App coexistence accounts**. Meta's [edit webhook reference](https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/reference/messages/edit/) documents edits to text or media captions within 15 minutes; its [revoke reference](https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/reference/messages/revoke/) documents deletion notifications within two days. Both require coexistence. Successful credential verification does not prove account eligibility.

The source owner enables optional `message_events: true`. It defaults to false and is omitted when false. The independent `CMAEG_NATIVE_WHATSAPP_MESSAGE_EVENTS_ENABLED` operator flag also defaults to false, including the checked-in ConfigMap. Authenticated authoring discovery exposes optional `native_whatsapp_message_events_enabled`, effective only with durable admission and recovery. The editor labels consent for coexistence incoming edits and deletions. Use the source's existing signed `messages` callback; no new credential, webhook endpoint, collection, or service is introduced.

CMA authenticates the original callback bytes using the current app secret and checks the configured WABA and phone. An edit carries its own unique outer message ID, sender, timestamp, `edit.original_message_id`, and `edit.message`. Text uses the standard nested `type: "text", text: {body: ...}` message shape. Meta's edit reference gives an image-caption example and describes text edits in its trigger definition; it does not give a separate text-edit example. A revoke carries `revoke.original_message_id`. Group-shaped changes, unsupported nested types, malformed identifiers and ambiguous content are refused. Sender identity remains an account of unknown actor kind.

Only a retained, admitted incoming ordinary text or media message from that source and sender can authorize a change. Eligibility uses the original provider type at capture, admission and execution; shared contacts and locations remain excluded even though they project to display text. Outgoing bot receipts, historical imports, Business App message echoes, control completions, and unretained messages do not establish original authority. A missing original receives a bounded 120-second retry opportunity for out-of-order delivery. Originals in the same callback batch are admitted first. After that opportunity, missing originals are refused.

The normalized events are the existing `cma.message.updated.v1` and `cma.message.deleted.v1` CloudEvents. They retain the outer provider event ID and exact provider timestamp, original message/event IDs and original author metadata. Edits contain `data.patch.text`. Original routing, consumer, provider, partition, and conversation are retained; changed addressing does not select a new agent. The Activity receipt is committed before provider work completes.

Caption changes emit only the updated visible text. Image, document, and video captions require the exact retained media ID, SHA-256, kind, and variant. The original attachment remains unchanged. A changed media identity is refused because the documented edit reference does not establish replacement-media custody. A webhook media URL never becomes a fetched URL or attachment authority. Caption removal is represented by an explicit empty caption. Audio/sticker edits and outgoing edit/delete operations are outside this feature.

A small encrypted original-message context is written to the existing interaction store before the original admission, only while both consent and the operator gate are enabled. It binds the original immutable facts, owner, source, sender and all three source credentials. Its expiry is three days from the original provider timestamp, within the existing interaction retention limit. The committed original routing manifest remains required: the locator alone grants no authority. Ordinary originals admitted earlier, or while the operator gate is off, remain usable but cannot be upgraded retroactively to authorize changes. No optional collection migration or new readiness marker is required; unavailable interaction storage fails new opted-in capture before acknowledgement.

Duplicate outer event IDs reuse the first retained facts and signed batch bytes, including rebatched retries. Conflicting message facts are refused. Turning off the operator admission gate stops new changes but permits replay and recovery of already admitted changes while original authority remains retained. Removing source consent or changing owner, source policy, source credentials, original consumer, or provider revokes pending execution. Execution rechecks the original encrypted credential proof and current source; it never depends on the issuance flag. After the original context expires, changes can no longer execute.

The new consent bit is excluded from existing typed group/control revisions, incoming-reaction authority, and Forms source hashes. Literal historical source bytes and revisions are pinned in tests. Existing Forms also bind the channel record version: a management write retains that pre-existing revocation fence, even when the edit only changes incoming-change consent. This feature does not weaken Forms generation checks.

Validation uses official-shaped signed callbacks and local record/provider HTTP fixtures. It covers text and caption edits, revoke, malformed/group payloads, original sender and media binding, credential rotation, original target retention, duplicates/rebatching, lost acknowledgement, gate/consent revocation, Activity visibility before provider work, and existing ordinary text/media/reaction/control/Form paths. Tests do not contact a recipient or activate a provider account.
